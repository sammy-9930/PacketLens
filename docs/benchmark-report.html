Scaling by thread count

Capture threads include one reader and any decode workers. With one thread, the reader also decodes. With four threads, one reads and three decode. Threaded packet output uses a separate writer. Metrics-only mode uses a separate reporter. The table counts readers and decode workers.

How it was measured

Google Benchmark replayed 16,384 synthetic 20-byte IPv4 packets per iteration through the capture pipeline and a counting sink. Values are medians across runs. Queue waits are average full-queue waits per iteration. IP throughput includes decoded IP headers and payload bytes. Timings include worker startup and shutdown. Live interface throughput can vary with packet sizes, socket behavior, and output costs.

To reproduce, build sniffer-benchmark and run ./sniffer-benchmark --benchmark_repetitions=3 --benchmark_out=rates.json --benchmark_out_format=json.
